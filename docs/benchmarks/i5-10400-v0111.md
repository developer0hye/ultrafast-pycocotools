# COCO val2017 on i5-10400: ultrafast 0.1.11

This is the measurement behind the README table and chart. Four released PyPI
wheels score identical saved predictions on one host, in fresh processes.

## Output agreement

pycocotools 2.0.11 is the reference. Each backend's complete `precision`,
`recall` and `scores` arrays are compared with it:

| Backend | bbox | segm | keypoints |
| --- | --- | --- | --- |
| ultrafast 0.1.11 | byte-identical | byte-identical | byte-identical |
| faster-coco-eval 1.8.0 | 3,650 precision cells differ, max 2.2e-16 | 6,714 precision cells differ, max 2.2e-16 | byte-identical |
| hotcoco 1.0.1 | precision as faster-coco-eval; 180 `scores` cells differ, max 0.095 | precision as faster-coco-eval; 60 `scores` cells differ, max 0.036 | byte-identical arrays; stats differ by 4.4e-16 |

Recall is identical for every backend, and all recorded evaluation parameters
match. hotcoco 1.0.1 shows the same sampled-score differences as 1.0.0; see the
[hotcoco comparison](../benchmark-hotcoco.md#sampled-score-compatibility) for a
two-image reproduction. Every timed run matched its backend's diagnostic
output hashes.

## Workload

- All 5,000 COCO val2017 images, including images without annotations.
- Saved YOLO26n, YOLO26n-seg and YOLO26n-pose predictions from the
  [Ultralytics PR #26101 evidence archive](https://github.com/developer0hye/ultrafast-pycocotools/releases/download/v0.1.7/ultralytics-pr26101-evidence-20260909.tar.gz):
  733,070 bbox, 724,953 segmentation and 134,663 pose detections. Input SHA-256
  hashes are recorded in the results.
- Standard COCO parameters: bbox/segm maxDets `[1, 10, 100]`, keypoints `[20]`.

## Method

- Driver: [`bench/hotcoco_benchmark.py`](../../bench/hotcoco_benchmark.py) with
  `--backends pycocotools faster hotcoco ufcoco --modes files --threads 2 --rounds 6`.
- Per task: one pycocotools oracle run and one array-export warmup per backend,
  both excluded from timing; then 6 rounds with backend order alternated each round.
  No run is excluded based on its timing, memory or agreement.
- Wall and CPU time cover GT and DT JSON loading, evaluator construction,
  `evaluate`, `accumulate` and `summarize`. Imports, inference and array export
  are excluded. Peak RSS is whole-process and includes imports and parsed inputs.
  MB is 1,000,000 bytes.
- `RAYON_NUM_THREADS=2` and `OMP_NUM_THREADS=2`; BLAS/NumExpr pools at 1. These
  are pool sizes, not CPU quotas. pycocotools is single-threaded. No CPU affinity.
- OS file caches were warm; this is not a cold-storage benchmark.

## Reproduce

```sh
curl -LO https://github.com/developer0hye/ultrafast-pycocotools/releases/download/v0.1.7/ultralytics-pr26101-evidence-20260909.tar.gz
tar xzf ultralytics-pr26101-evidence-20260909.tar.gz
uv venv --python 3.12 .venv-readme
uv pip install --python .venv-readme/bin/python -r bench/readme-requirements.txt
.venv-readme/bin/python bench/hotcoco_benchmark.py \
  --inputs ultralytics-pr26101-evidence-20260909/inputs --out bench/out/readme \
  --backends pycocotools faster hotcoco ufcoco --modes files --threads 2 --rounds 6
uv pip install --python .venv-readme/bin/python matplotlib
.venv-readme/bin/python bench/plot_readme.py --results bench/out/readme/results.json
```
